# Alma Lab Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `almaapitk.lab`: a full-screen three-pane Textual app plus a headless `almaapitk-lab` command that run almaapitk operations and write one evidence record per call.

**Architecture:** A UI-free core (`catalog`, `capture`, `normalize`, `expect`, `evidence`, `redact`, `runner`) does all the work; the headless CLI and the Textual app are thin front ends over `runner.run_operation`. Requests are captured, and writes gated, by wrapping the client's `_session.request` (the one chokepoint every `AlmaAPIClient` verb uses).

**Tech Stack:** Python ≥3.12, requests/urllib3 (existing), Textual 8.x (optional extra `lab`), pytest.

**Spec:** `docs/superpowers/specs/2026-11-10-alma-lab-design.md`

## Global Constraints

- Package `almaapitk.lab`; extra `lab = ["textual>=8.0.0,<9.0.0"]`; console script `almaapitk-lab = "almaapitk.lab.cli:main"`. Core install gains no dependency; importing `almaapitk.lab.cli` without Textual must work for every headless command.
- Python `>=3.12`; must run in Windows Terminal (no POSIX-only calls: no `termios`, no `fcntl`, paths via `pathlib`).
- Default environment `SANDBOX`. The API key is never written to evidence, stdout or logs; the `Authorization` header is stored as `apikey ***`.
- Write = any non-GET request. Every write passes the gate before it is sent: Sandbox needs a yes, Production needs the typed operation name (app) or `--confirm-write <operation name>` (headless). Sandbox headless writes need `--allow-writes`.
- The tool's client retries GET only (adapters' `max_retries` replaced via `Retry.new(allowed_methods=frozenset({"GET"}))`, keeping each adapter's forcelist).
- Evidence dir default `./alma-lab-evidence/`, file `<YYYY-MM-DD>/<HHMMSS>-<operation>.json` (suffix `-2`, `-3` on collision); warn when not gitignored.
- Generators/iterators returned by a method are materialised with a cap of 1000 items; the record says `"capped": true` when hit.
- Logging via `almaapitk.alma_logging.get_logger("lab", environment)`; no `print` outside `cli.py` output functions.
- Synthetic IDs only in tests and docs (R9).

## Review Focus

1. **A non-JSON or empty Alma body** (XML error page, 204 No Content) must still produce a record and a readable Result pane, not a crash. → Task 2 test `test_capture_records_non_json_body`.
2. **Typing into fields with the wrong type** (`limit=abc`, `True` for a bool) must show a field error before sending, not a traceback. → Task 5 test `test_coerce_rejects_bad_int_with_field_name`.
3. **An exception mid-method after a write was already sent** (multi-write method, second write fails or is cancelled) must record the first write as sent. → Task 5 test `test_cancel_second_write_records_first_as_sent`.
4. **Evidence dir not writable** must surface as a clear error in headless (exit 2) and app (notification), never lose the response silently. → Task 4 test `test_write_record_unwritable_dir_raises_evidence_error`.
5. **A huge response** (thousands of rows) must not freeze the app: the result tree loads lazily. → Task 9 test `test_large_response_tree_is_lazy`.

**Interfaces — Produces:**
- `@dataclass(frozen=True) class Param: name: str; annotation: str; kind: Literal["str","int","float","bool","choice","json","unsupported"]; required: bool; default: Any; help: str; choices: tuple[str, ...] = ()`
- `@dataclass(frozen=True) class Operation: domain: str; name: str; params: tuple[Param, ...]; verbs: frozenset[str]; multi_write: bool; doc: str` with properties `qualname -> "Domain.name"`, `writes -> bool` (any verb ≠ GET, or `"UNKNOWN"` in verbs), `sendable -> bool` (no required `unsupported` param).

- `classify_verbs(cls: type, method_name: str) -> frozenset[str]`: AST of the method; collects `self.client.get/post/put/delete` → `GET/POST/PUT/DELETE`, follows calls to `self.<other public or private method>` of the same class recursively (cycle-safe); hints override; nothing found → `{"UNKNOWN"}`.
- `hints.py`: `HINTS: dict[str, dict]` keyed by qualname, keys `verbs`, `choices` (param → tuple), `body_param`, `incomplete_reason`. `INCOMPLETE` qualnames: `ResourceSharing.create_lending_request_from_citation` ("PubMed/Crossref lookup is not captured").

### Task 2: Request capture and the write gate

**Files:** Create `src/almaapitk/lab/capture.py`; Test `tests/unit/lab/test_capture.py`

**Interfaces — Produces:**
- `@dataclass class CapturedRequest: method: str; url: str; headers: dict[str,str]; body: str | None; status: int | None; response_headers: dict[str,str]; response_body: str | None; duration_ms: int; tracking_id: str | None; attempts: list[dict]; error: str | None; sent: bool`
- `class WriteCancelled(AlmaOperationCancelled)`
- `WriteGate = Callable[[str, str, str | None], bool]` (method, url, body) → approve?
- `class Recorder: def __init__(self, client: AlmaAPIClient, gate: WriteGate | None)`; `install() -> None` (wraps `client._session.request`, idempotent); `start() -> None` (clears); `requests: list[CapturedRequest]`.
- `make_lab_client(environment: str) -> AlmaAPIClient` — builds the client and replaces every mounted adapter's `max_retries` with `.new(allowed_methods=frozenset({"GET"}))`.

Behaviour: non-GET → call gate first; gate None or False → append a `CapturedRequest(sent=False)` and raise `WriteCancelled`. Mask `Authorization` value to `apikey ***`; strip `apikey` from URLs. `attempts` from `response.raw.retries.history` (`{"status":…, "error":…}` each) when present. Tracking ID from the JSON/XML errorList when present. Exceptions from the wrapped call are recorded (`error`) and re-raised.

### Task 3: Normalise results and evaluate expectations

**Files:** Create `src/almaapitk/lab/normalize.py`, `src/almaapitk/lab/expect.py`; Test `tests/unit/lab/test_normalize.py`, `tests/unit/lab/test_expect.py`

**Interfaces — Produces:**
- `normalize_result(value: Any, cap: int = 1000) -> tuple[Any, bool]` → (JSON-safe data, capped). `AlmaResponse` → its JSON (or text); XML string → `{"xml": text, "parsed": <dict tree>}`; generators materialised to cap; dataclasses/objects → `repr`.
- `xml_to_tree(text: str) -> dict` — elements as `{"tag", "attrs", "text", "children"}`.
- `resolve(data: Any, path: str) -> Any` — dotted keys, `[N]` indexes, and `name[attr=value]` filters over lists/children (e.g. `record.datafield[tag=505].subfield[code=a]`); raises `KeyError` with the failing segment.
- `@dataclass class Expectation: text: str; target: str; op: Literal["==","exists","contains"]; value: str | None`; `parse_expectation(text: str) -> Expectation` (raise `ValueError` with a usage hint).
- `evaluate(exp: Expectation, *, result: Any, requests: list[CapturedRequest], error: str | None) -> dict` → `{"text","outcome": "passed"|"failed"|"error","actual"}`. Targets: `status` (last request), `error`, `http[N].status`, `http[N].body.<path>`, otherwise a path in the normalised result. Comparisons are string-based after `str()`, with numbers compared numerically when both parse.

### Task 5: Runner

**Files:** Create `src/almaapitk/lab/runner.py`; Test `tests/unit/lab/test_runner.py`

**Interfaces — Consumes:** Tasks 1–4. **Produces:**
- `coerce_inputs(op: Operation, raw: dict[str, str]) -> dict[str, Any]` — raises `InputError(field, message)`; blank optional → omitted; json kind parsed with `json.loads`; bool accepts `true/false/yes/no/1/0`.
- `class Session: def __init__(self, environment: str = "SANDBOX", evidence_dir: Path = Path("alma-lab-evidence"), gate: WriteGate | None = None, source: str = "app", command: str | None = None)` — one lab client per session, `domain(cls)` instances cached.

- `Session.rerun(record: EvidenceRecord) -> EvidenceRecord`.
